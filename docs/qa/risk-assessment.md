# Risk Assessment

Risk = Likelihood × Impact, assessed for the business flows this project tests. Scored Low/Medium/High.

| ID | Risk | Likelihood | Impact | Overall | Mitigation in this project |
|---|---|---|---|---|---|
| RISK-01 | A regression in Quotation → Sales Order → Sales Invoice silently produces a wrong financial total (the business's revenue-recording path). | Medium | High | **High** | TC-05 is a true end-to-end test asserting the final invoice total matches the originating order — the single highest-value test in the suite. This exact class of bug was found live during this project ([DEFECT-002](../bug-reports/DEFECT-002-rate-reset-on-document-conversion.md)). |
| RISK-02 | A background/async feature (search indexing, email queue, notifications) appears broken with no UI error, and is misdiagnosed as a feature bug rather than an infrastructure issue. | Medium | Medium | **Medium** | TC-13 (global search) surfaced exactly this ([DEFECT-001](../bug-reports/DEFECT-001-scheduler-crash-from-orphaned-app.md)) — the retry/timeout design in that test, and this write-up, exist specifically so the next person doesn't have to re-diagnose it from scratch. |
| RISK-03 | A test asserts something that is trivially true regardless of whether the feature works (a "green but meaningless" test), hiding real failures. | Medium | High | **High** | Found and fixed once in this suite itself (original `global-search.spec.ts` asserted on an echoed input string rather than a real search result — see [Exploratory Testing Report](exploratory-testing-report.md), EXP-01). General mitigation: prefer asserting on a *consequence* only the real feature can produce (a toast, a status change, a specific result row) over asserting on arbitrary visible text. |
| RISK-04 | Permission/role-based access control regresses (e.g. a non-Administrator role gains or loses access it shouldn't). | Unknown (not tested) | High | **Unmitigated — documented gap** | Out of scope for this pass; only `Administrator` is exercised. See README Future Improvements. |
| RISK-05 | A UI redesign changes selectors/markup and silently breaks automation without a corresponding application bug. | High (already happened once, mid-project — see Design Notes) | Medium | **Medium** | Page Object Model centralizes all selectors in `tests/ui/pages/*.ts`; when this ERPNext version's redesigned desk UI (`/desk`, toast-based confirmations, ARIA-role dropdowns) broke the original selectors, the fix was localized to a handful of files rather than scattered across every spec. |
| RISK-06 | Test data from one test run collides with another (e.g. two tests creating the same-named Customer). | Low | Medium | **Low** | `fixtures/testData.ts` generates timestamp+random-suffixed names for every created record. |
| RISK-07 | CI uses stale or manually-configured credentials that don't exist on a freshly provisioned site. | Low | High | **Low** | Session-login auth (`/api/method/login`) instead of a static API key — works identically against any newly created site, local or CI. |
| RISK-08 | Environment-level issues (proxy misconfiguration, crashed containers, orphaned app files) are mistaken for application or test defects, wasting investigation time. | Medium | Medium | **Medium — partially realized during this project** | Both real defects in this repo's bug-reports were environment-adjacent, not application logic bugs in the narrow sense; documenting root cause (not just "test flaked, reran it") is the stated mitigation going forward. |

## Residual risk after this pass

The highest remaining *unmitigated* risk is **RISK-04** (no role-based permission testing) — flagged explicitly rather than silently left out, per this project's "never fabricate coverage" principle.
